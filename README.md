# GridBattle

GridBattle is a turn-based tactical gridworld project for Modern Game AI Algorithms. The project combines a playable game, procedural map generation, and AI-based evaluation. The main research goal is to study how different PCG settings affect difficulty, pacing, and agent performance.

The two main entry points are:

```bash
python play.py
python experiment.py ...
```

`play.py` is for playing the game with the Pygame UI.  
`experiment.py` is for running headless agent experiments in the real Griddly-backed environment.

## Game overview

GridBattle is a small turn-based tactical combat game on a 2D grid.

The player wins by defeating all enemies. The player loses when their health reaches zero, or when the turn limit is reached during an experiment.

Each turn, the player can move and attack. Enemies then move toward the player and attack when they are close enough. Enemy movement is pathfinding-based: enemies try to approach the player through the available walkable tiles.

### Terrain

- **Hill**: gives a range advantage.
- **Bush**: gives a chance to dodge incoming damage.
- **Bunker**: absorbs 1 incoming damage once, then collapses. Bunkers do not block movement.

### Items

- **Dual berettas**: allows a second attack while active.
- **Shotgun**: strengthens close-range attacks.
- **Golden gun**: provides a powerful short-duration attack effect.
- **Vehicle**: allows extended movement while active.

Items can be picked up from the map and activated by agents or the player.

## Procedural map generation

Maps are generated by `grid_battle/pcg.py`. The generator creates structurally valid maps by checking that the player can reach positions from which all enemies can be attacked.

Structural validity does not mean the map is balanced. The experiments therefore use agents to evaluate whether generated maps are too easy, too hard, or tactically interesting.

### Map types

- **baseline**: scattered obstacle layout with relatively general-purpose structure.
- **random_walk**: cave-like layout generated through random walk carving, producing corridors and chokepoints.
- **arena**: more open combat-focused layout with obstacle placement designed around arena-style fights.

### PCG profiles used in experiments

The screening experiment varies size-aware and map-type-aware profiles:

- **enemy profile**: controls enemy count while scaling with map size.
- **item profile**: controls how many support items appear, also scaled by map size.
- **wall profile**: controls wall density, interpreted differently per map type so arenas stay open and random-walk maps stay cave-like.

The experiment CSV stores both the profile names and the concrete settings used.

## Agents

### Random agent

The random agent chooses legal actions randomly. It is mainly used as a sanity check, not as a serious balancing target.

### Heuristic agent

The heuristic agent is a greedy tactical baseline. It:

1. activates useful inventory items,
2. attacks immediately if an enemy is in range,
3. otherwise finds a shortest path toward a tile from which an enemy can be attacked,
4. moves toward that tile,
5. attacks after moving if possible,
6. uses a second attack when dual berettas are active.

This agent represents a competent but non-searching player.

### MCTS agent

The MCTS agent uses Monte Carlo Tree Search with UCT. It searches possible future turns using an internal forward model, then returns the most visited root action.

Available MCTS profiles:

- `mcts_small`: 50 iterations, rollout depth 10
- `mcts_medium`: 200 iterations, rollout depth 30
- `mcts_strong`: 800 iterations, rollout depth 40

The experiments mainly use `mcts_small` and `mcts_medium`. Final game outcomes are measured in the real `GridBattleEnv`, not in the simulator. The simulator is only used internally by MCTS for planning.

## Run experiments

Experiments are headless: they do not open the UI. They use the real Griddly-backed game environment.

Quick smoke test:

```bash
python experiment.py smoke
```

Run one evaluation:

```bash
python experiment.py eval \
  --agent heuristic \
  --size medium \
  --map-type random_walk \
  --episodes 20
```

Run with MCTS:

```bash
python experiment.py eval \
  --agent mcts_medium \
  --size large \
  --map-type arena \
  --episodes 20
```

Use multiple worker processes:

```bash
python experiment.py eval \
  --agent mcts_medium \
  --size large \
  --map-type baseline \
  --episodes 50 \
  --workers 8
```

### PCG screening experiment

The main PCG balancing experiment is:

```bash
python experiment.py pcg-screen \
  --episodes 20 \
  --workers 16 \
  --overwrite \
  --csv-out results/pcg_screening.csv
```

Preview the planned cells without running:

```bash
python experiment.py pcg-screen --dry-run
```

The output CSV contains one row per episode, including:

- agent name and MCTS settings,
- size and map type,
- enemy/item/wall profiles,
- concrete PCG settings,
- win/loss result,
- turns, damage, final HP, enemies remaining,
- generated enemy count and obstacle density,
- reachability, chokepoints, dead ends, and enemy-distance metrics.

Plotting and analysis should be done in a separate script, not in `experiment.py`.

## Replay a game

You can replay a specific generated game by using the same seed and episode index.

Text replay:

```bash
python experiment.py replay \
  --agent mcts_medium \
  --size large \
  --map-type baseline \
  --seed 11 \
  --episode 3
```

Write a replay log:

```bash
python experiment.py replay \
  --agent mcts_medium \
  --size large \
  --map-type baseline \
  --seed 11 \
  --episode 3 \
  --log-out results/replays/mcts_medium_large_baseline_ep3.txt
```

Replay with the normal Pygame UI:

```bash
python experiment.py replay \
  --agent mcts_medium \
  --size large \
  --map-type baseline \
  --seed 11 \
  --episode 3 \
  --ui \
  --pause
```

UI replay controls:

- `Space`: pause/resume
- `Enter` or `Right`: step once
- `R`: reset the same replay
- `Esc` or `Q`: quit

Replay uses deterministic seeding, so the same seed, episode, agent, and settings should reproduce the same game.

## Recommended workflow

1. Play a few maps manually:

```bash
python play.py
```

2. Run a smoke test:

```bash
python experiment.py smoke --workers 4
```

3. Run the PCG screen:

```bash
python experiment.py pcg-screen \
  --episodes 20 \
  --workers 16 \
  --overwrite \
  --csv-out results/pcg_screening.csv
```

4. Analyze the CSV with a separate plotting script.

5. Replay interesting wins/losses:

```bash
python experiment.py replay \
  --agent mcts_medium \
  --size large \
  --map-type arena \
  --seed 11 \
  --episode 5 \
  --ui \
  --pause
```
