# Report Figure Commentary

This file is intentionally hand-written rather than generated by `results_analysis/make_report_assets.py`. The PNG figures are kept clean for insertion into the report, while this commentary supplies the interpretation, discussion points, and recommended use of each asset.

## Recommended Story

The strongest report narrative is:

1. We built a Griddly-backed grid combat game with procedural maps, combat items, enemies, and terrain structure.
2. We evaluated three broad questions: whether the generator can create a difficulty ladder, whether stronger planning agents actually solve more content, and which generator factors control difficulty.
3. We used four agents as behavioral probes: random, heuristic, MCTS-small, and MCTS-medium.
4. The final generator settings create a clean progression: small maps are tutorial-like, medium maps separate heuristic and MCTS play, and large maps create longer tactical problems.
5. MCTS wins more because it can evaluate future consequences of movement, combat, item pickup, and spatial traps. The heuristic agent is fast and sensible locally, but it can misjudge delayed rewards and bottlenecks.

## Figure 1: Final Validation Difficulty Ladder

Asset: `figures/01_final_validation_difficulty_ladder.png`

Use this as the headline result. It shows aggregate final-validation win rate by map size and agent strength, with 95% Wilson confidence intervals.

What we see:

- Small maps are intentionally easy. Random is already fairly successful, and all stronger agents solve them reliably.
- Medium maps are the best evidence of calibrated challenge. Random performs poorly, the heuristic agent improves substantially, and MCTS-medium performs best.
- Large maps are harder and longer. The gap between local heuristic play and deeper MCTS planning remains visible.

What it means:

- The final generator is not producing arbitrary noise. It creates a useful difficulty ladder across size.
- Stronger agents do better in the expected order, which is evidence that the environment rewards skill rather than luck alone.
- The confidence intervals help show that the main separation is not just seed noise.

Report angle:

Use this figure early in the results section. The caption should make clear that map size is not the only generator factor, but it is the clearest high-level view of the final validation suite.

## Figure 2: Final Validation Skill Gap By Configuration

Asset: `figures/02_final_validation_skill_gap_dumbbell.png`

Use this if the report has space for a detailed follow-up after Figure 1. It compares win rates for the agents on each final generator configuration.

What we see:

- The dumbbell gap between heuristic and MCTS-medium is largest on configurations where lookahead matters most.
- Small baseline settings cluster near high success, which confirms they behave like accessible introductory content.
- Medium and large settings create more varied outcomes, especially where map structure and enemy pressure interact.

What it means:

- The generator can produce levels that expose agent capability differences.
- MCTS is not simply winning because every map is easy. It retains an advantage in configurations where the heuristic agent is imperfect.
- This figure supports the claim that final configurations were chosen to balance playability with meaningful skill expression.

Report angle:

Use this figure to move from the simple aggregate story to the configuration-level story. It is especially useful if the report discusses why the final settings were selected.

## Figure 3: Paired Same-Map Outcomes

Asset: `figures/03_paired_heuristic_vs_mcts_outcomes.png`

Use this as the strongest evidence that MCTS solves more of the same content, not merely a different sample of easier seeds.

What we see:

- Each bar uses matched map seeds for heuristic and MCTS-medium.
- "Both win" represents maps solved by both agents.
- "MCTS only" represents maps where MCTS succeeds and the heuristic fails.
- "Heuristic only" is small or absent in the most important settings.
- "Both lose" marks settings that are too difficult for both agents on some seeds.

What it means:

- The paired design controls for map randomness. When MCTS-only occupies a large fraction of a bar, that is direct evidence that deeper planning changes the outcome on the same generated maps.
- On easier maps, both agents often win, so the MCTS advantage is hidden by saturation.
- On challenging maps, the MCTS-only region becomes the key story: MCTS can recover from positions or exploit opportunities that the heuristic cannot evaluate reliably.

Report angle:

This figure should appear near the discussion of agent behavior. It makes the result intuitive because it turns "higher win rate" into "more shared-seed maps solved".

## Figure 4: Medium Enemy Tuning Heatmap

Asset: `figures/04_medium_enemy_tuning_balance_heatmap.png`

Use this to explain why `medium_plus` exists and why final medium maps use it.

What we see:

- The heatmap compares open-wall medium maps across map type, enemy profile, and item setting.
- Cell color encodes a balance score.
- Cell text gives the score plus heuristic and MCTS-medium win rates.
- Normal enemies often make the environment too easy, especially when item availability is generous.
- Heavy enemies can push the environment toward harsh or mixed behavior.
- `medium_plus` often creates the most useful middle region: heuristic remains imperfect while MCTS stays strong.

What it means:

- Enemy profile is a more reliable tuning knob than map type alone for medium maps.
- The goal was not simply to make the game harder. The goal was to keep the problem solvable by better planning while preventing the heuristic from saturating.
- `medium_plus` helps create this separation.

Report angle:

Use this figure in the methodology or tuning subsection. It demonstrates that final settings were selected empirically, not by guesswork.

## Figure 5: OFAT Factor Sensitivity

Asset: `figures/05_ofat_factor_sensitivity.png`

Use this to summarize the one-factor-at-a-time sensitivity experiment.

What we see:

- Player HP and enemy HP have very large effects on win rate.
- Enemy profile is the strongest procedural-content control among the generator-facing knobs.
- Size, item profile, wall profile, and map type also matter, but their impact is generally smaller or more agent-dependent.

What it means:

- Combat-rule parameters can dominate procedural map effects.
- If HP is allowed to vary freely, it can overwhelm the more interesting PCG variables.
- This justifies fixing core combat balance in final validation and using map size, structure, enemies, items, and walls as the main PCG design space.

Report angle:

This figure is useful for explaining experimental discipline. It shows why we separated "game rule balance" from "procedural content balance" rather than mixing all factors together.

## Figure 6: HP Sensitivity Curves

Asset: `figures/06_hp_sensitivity_curves.png`

Use this immediately after Figure 5 if space allows. It gives the detailed shape behind the HP result.

What we see:

- Increasing player HP quickly raises win rates and can saturate stronger agents.
- Increasing enemy HP sharply suppresses win rates, especially for agents that rely on direct combat opportunities.
- The curves are steep compared with many map-generation factors.

What it means:

- HP is not a subtle PCG knob in this project. It changes the fundamental game economy.
- The agents' apparent skill can be distorted if HP is varied too aggressively.
- Keeping HP stable in final validation makes the final results easier to interpret as procedural level-design results.

Report angle:

Use this as a supporting figure. It is especially valuable for the discussion section because it explains an important design choice: fixing combat rules before evaluating final procedural maps.

## Figure 7: Structure Versus Pacing

Asset: `figures/07_structure_vs_pacing.png`

Use this to connect map topology to gameplay pacing.

What we see:

- The x-axis shows average chokepoints.
- The y-axis shows average turns for MCTS-medium.
- Random-walk maps tend to appear in the high-chokepoint, long-duration region.
- Arena and baseline maps generally produce more open or direct play.

What it means:

- Difficulty is not only about win rate. Procedural structure also changes the rhythm of play.
- Chokepoints create navigation constraints, delayed engagements, and longer planning horizons.
- MCTS benefits from lookahead in these situations, but it also takes longer games because movement and engagement decisions unfold over more turns.

Report angle:

Use this in the discussion to show design maturity. It expands the evaluation beyond "does the agent win" into "what kind of gameplay does the generator produce".
